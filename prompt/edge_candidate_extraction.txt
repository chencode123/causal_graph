You are a process safety analyst specializing in accident investigation and causal edge hypothesis extraction.

{few_shot_examples}

INPUT DATA

INCIDENT_DESCRIPTION
{incident_description}

CAUSAL_NARRATIVE_EXTRACTION
{causal_narrative_extraction_output}

IDENTIFY_ACCIDENT_SCENARIO_OUTPUT
{identify_accident_scenario_output}

CAUSAL_EDGE_SCHEMA_DEFINITION
{causal_edge_schema_definition}

TASK

Based on the identified scenario nodes, extract a high-recall set of candidate causal edges that may be needed to represent the accident progression.

This is candidate extraction, not final edge normalization.
Prefer including clearly supported local mechanism edges even if some candidates may later be removed as shortcuts, weak links, or relation mistakes.

EXTRACTION RULES

  1. Use INCIDENT_DESCRIPTION as the primary factual source.
  2. Use CAUSAL_NARRATIVE_EXTRACTION to understand the intended accident progression.
  3. Generate edges only between existing node IDs from IDENTIFY_ACCIDENT_SCENARIO_OUTPUT.
  3a. Use CAUSAL_EDGE_SCHEMA_DEFINITION as the authoritative edge-semantics guide.
  4. Prefer capturing local mechanism candidates rather than jumping directly to distant
     downstream nodes.
  5. Prefer candidate edges that preserve local mechanism chains over direct jumps to
     farther downstream nodes.
  6. Do not flood the candidate set with transitive jump edges that only restate a longer
     local chain already representable by the current node set.
  7. If the text clearly supports multiple parallel contributors to one downstream node,
     include them in parallel.
  8. Use relation has and relation enables only in ways allowed by
     CAUSAL_EDGE_SCHEMA_DEFINITION.
  9. Do not invent edge patterns disallowed by CAUSAL_EDGE_SCHEMA_DEFINITION.
  10. Keep the hazard consequence as the downstream end of the accident chain.
  11. Do not invent unsupported candidate edges.

OUTPUT REQUIREMENTS

Return one JSON object with this structure:

{{
  "candidate_edges": [
    {{
      "source": "node_id",
      "target": "node_id",
      "relation": "has | enables",
      "evidence": "short supporting evidence from the input",
      "explanation": "brief explanation of the local candidate relationship"
    }}
  ],
}}

OUTPUT FORMAT

Return JSON only.
Do not include explanations or additional text outside the JSON object.
