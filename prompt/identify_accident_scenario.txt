TASK

Based on the IDENTIFIED_HAZARD_CONSEQUENCE, the
CAUSAL_NARRATIVE_EXTRACTION, the SCENARIO_CANDIDATE_EXTRACTION_OUTPUT, and the
SCENARIO_STRUCTURE_VALIDATION_OUTPUT, produce the final normalized accident
scenario output that will be used for edge linking.

You must strictly follow the provided SCHEMA and SCHEMA_DEFINITION.
Use SCENARIO_CANDIDATE_EXTRACTION_OUTPUT as the candidate pool and
SCENARIO_STRUCTURE_VALIDATION_OUTPUT as the normalization guide.

EXTRACTION RULES

  1. Use SCENARIO_CANDIDATE_EXTRACTION_OUTPUT as the candidate source and
     SCENARIO_STRUCTURE_VALIDATION_OUTPUT as the primary normalization guide.

  2. The hazard_consequence must copy the node provided in IDENTIFIED_HAZARD_CONSEQUENCE.
 
  3. Preserve evidence and explanation from supported candidate nodes whenever possible.

  4. Do not invent new unsupported nodes beyond what is justified by the candidate
     extraction and validation guidance.

  5. If SCENARIO_STRUCTURE_VALIDATION_OUTPUT marks a candidate as over-merged, split it in
     the final output if the candidate pool already provides the required local roles.

  6. If SCENARIO_STRUCTURE_VALIDATION_OUTPUT marks a step as missing and the candidate pool
     already contains an adequate node for that local role, include it in the final output.

  7. Retain only causally reusable condition nodes. Remove purely descriptive or redundant
     candidate conditions.

  8. The final node set should be coherent, minimally sufficient, and stable for downstream
     edge linking.

  9. Each final event node should represent one local causal role only. Do not let one event
     node simultaneously represent an operational action, a physical release, an ignition
     step, and a downstream accident consequence.

  10. If the candidate pool already separates release, transport or dispersion, ignition,
      flame propagation or flashback, and final consequence, preserve that separation unless
      validation guidance explicitly supports merging.
 
  11. Represent release and dispersion as event nodes rather than condition
      nodes.
      When the report distinguishes release mode, prefer event labels such as
      "InstantRelease" or "ContinuousRelease".

  12. Only merge candidates when they are tightly coupled and jointly define the same local
      mechanism. Do not merge across different causal stages.

  13. Keep the final output grounded in the candidate evidence and aligned with the causal
      narrative.

Source rules

If the information is derived from the candidate extraction and validated
against the scenario structure, set source to "incident_description".

If the information cannot be determined, use "Not specified".

Return a JSON object that strictly follows the structure defined in SCHEMA.

The output must:

- Use the exact field names defined in the SCHEMA
- Use only the allowed values specified in the SCHEMA
- Include evidence quotes whenever required
- Use "Not specified" if the information cannot be determined

  - set passed to true or false

  - if passed is true, keep reason brief and specific

Return JSON only.
