TASK

Based on the IDENTIFIED_HAZARD_CONSEQUENCE, the
CAUSAL_NARRATIVE_EXTRACTION, the SCENARIO_CANDIDATE_EXTRACTION_OUTPUT, and the
SCENARIO_STRUCTURE_VALIDATION_OUTPUT, produce the final normalized accident
scenario output that will be used for edge linking.

You must strictly follow the provided SCHEMA and SCHEMA_DEFINITION.
Use SCENARIO_CANDIDATE_EXTRACTION_OUTPUT as the candidate pool and
SCENARIO_STRUCTURE_VALIDATION_OUTPUT as the normalization guide.
The goal is a single primary-pathway, minimally sufficient, normalized node set.

EXTRACTION RULES

NORMALIZATION BASIS

  1. Use SCENARIO_CANDIDATE_EXTRACTION_OUTPUT as the candidate source and
     SCENARIO_STRUCTURE_VALIDATION_OUTPUT as the primary normalization guide.

  2. Use INCIDENT_DESCRIPTION as the factual source for confirming that final node choices
     remain directly supported when applying the normalization guidance.
 
  3. Preserve evidence and explanation from supported candidate nodes whenever possible.

  4. Do not invent new unsupported nodes beyond what is justified by the candidate
     extraction and validation guidance.

  5. Do not preserve alternative hypothesis branches in the final normalized scenario
     unless the SCENARIO_STRUCTURE_VALIDATION_OUTPUT explicitly requires them.

SELECTION AND COVERAGE

  6. Use SCENARIO_STRUCTURE_VALIDATION_OUTPUT as the action guide for final normalization.
     Apply its issue definitions and normalization guidance when deciding what to split,
     include, remove, retain, merge, or materialize in the final node set.

  7. When normalization guidance identifies a supported missing role that is not adequately
     represented in the candidate pool, use INCIDENT_DESCRIPTION only to confirm and
     materialize the minimal directly supported node needed to satisfy that guidance.
     Treat must_add_nodes as the guidance field for these required additions.

  8. Prefer the smallest node set that still preserves the required local mechanism chain.
     If multiple candidate nodes express the same local causal role, retain one normalized
     node rather than multiple near-duplicates.

  9. Normalize to one coherent pathway from upstream mechanism to hazard consequence.
     Do not retain side branches, witness-chronology variants, or descriptive-only nodes
     once the main pathway is adequately represented.

Source rules

If the information is derived from the candidate extraction and validated
against the scenario structure, set source to "incident_description".

If the information cannot be determined, use "Not specified".

OUTPUT REQUIREMENTS

Return a JSON object that strictly follows the structure defined in SCHEMA.

The output must:

- Use the exact field names defined in the SCHEMA
- Use only the allowed values specified in the SCHEMA
- Include evidence quotes whenever required
- Use "Not specified" if the information cannot be determined
- Preserve only nodes that serve a necessary causal role or a necessary supporting
  has-relationship in the final normalized pathway
- Prefer stable normalized wording over incident-specific paraphrase variants when
  two candidates represent the same causal role

OUTPUT FORMAT

Return JSON only.
Do not include explanations or additional text outside the JSON structure.
