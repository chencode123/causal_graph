SCHEMA DEFINITION

The output must strictly follow the provided JSON schema.
Each field has a specific meaning and must be filled according to the rules
below.

General Rules

Evidence

The "evidence" field must contain a short quote copied directly from the source
that supports the extracted value.

If source = "incident_description":
The evidence must be copied verbatim from the incident report text.

Do not invent, paraphrase, or infer evidence.

If no supporting evidence can be found, set:
evidence = "N/A"
source = "Not specified".

Source

The "source" field indicates where the information was obtained.
The allowed source values are listed in each node definition.

Allowed values:

incident_description  
Information directly extracted from the incident report.


Not specified  
Used when the information cannot be determined from the incident report or reliable external knowledge sources.

Node ID

Each node must include a `node_id`, which serves as a unique identifier in the graph.

The `node_id` must follow the prefix corresponding to the node type:

- H#  → HazardConsequence nodes
- En# → Entity nodes
- C#  → Condition nodes
- Ev# → Event nodes

Where # is a sequential integer starting from 1 within each node category.

Examples:
H1, En1, C1, Ev1

Rules:
- Each node must have exactly one `node_id`.
- All `node_id` values must be unique within the output.
- The prefix must match the node's `node_type`.
- Do not invent other ID formats.
- The `node_id` is only an identifier and must not contain semantic meaning.

--------------------------------------------------
Material
--------------------------------------------------

Definition
The hazardous substance involved in the accident scenario.

This refers to the chemical or material present in the process that
participates in release events, dispersion events, ignition, or hazard
consequence.


--------------------------------------------------
Location
--------------------------------------------------

Definition
The physical place or equipment where the accident-related event occurs.

This may include process units, storage tanks, pipelines, packaging areas, or
other facility locations relevant to the accident.

--------------------------------------------------
IntermediateEvent
--------------------------------------------------

An intermediate event that occurs after the initiating event and before the
final hazard consequence, only when a necessary accident-process step cannot be
adequately represented by the existing node types.

Use IntermediateEvent sparingly.

Do not create an IntermediateEvent if the same accident logic can already be represented by:
- MechanicalFailure
- InitiatingEvent
- IgnitionSource
- Entity nodes
- Condition nodes

IntermediateEvent should only be used for a process-significant transition that
adds unique causal information and cannot be expressed by the other node types.

Do not use IntermediateEvent merely to restate an observed outcome such as
overpressure, explosion, or fire unless that stage is distinctly necessary in
the accident progression.

Event labels

Event labels must use one of the schema-supported labels:
- InitiatingEvent
- MechanicalFailure
- IgnitionSource
- IntermediateEvent
- InstantRelease
- ContinuousRelease
- Dispersion

Use event labels to reflect the local causal role described by the report, such as:
- InitiatingEvent
- MechanicalFailure
- IgnitionSource
- IntermediateEvent
- InstantRelease
- ContinuousRelease
- Dispersion

When release or dispersion is described as a process-significant step in the
accident progression, represent it as an Event rather than a Condition.

If the described event semantically matches InstantRelease,
ContinuousRelease, or Dispersion, prefer using that more specific event label
rather than the more generic InitiatingEvent or IntermediateEvent label.

--------------------------------------------------
InstantRelease
--------------------------------------------------

Definition
A release event in which hazardous material is discharged suddenly or over a
short interval.

Use InstantRelease when the report describes a rapid loss of containment, abrupt discharge,
bursting release, or a one-time sudden emission.

If the event semantically matches an instantaneous release, prefer
InstantRelease over InitiatingEvent or IntermediateEvent.

--------------------------------------------------
ContinuousRelease
--------------------------------------------------

Definition
A release event in which hazardous material is discharged continuously or over
an extended interval.

Use ContinuousRelease when the report describes ongoing leakage, venting, steady discharge,
or persistent release over time.

If the event semantically matches a continuous release, prefer
ContinuousRelease over InitiatingEvent or IntermediateEvent.

--------------------------------------------------
Dispersion
--------------------------------------------------

Definition
A dispersion event in which released material spreads, travels, accumulates, or
forms a cloud in the surrounding environment.

Use Dispersion when the report describes vapor cloud formation, gas spreading,
material transport through air, or accumulation of released material in a
nearby area.

If the event semantically matches dispersion, prefer Dispersion over
InitiatingEvent or IntermediateEvent.

--------------------------------------------------
Phase
--------------------------------------------------

Definition
The physical phase of the material at the time of the accident.

This condition describes whether the material exists as liquid, vapor, solid,
or a two-phase mixture, which can influence release behavior and hazard
consequences.


--------------------------------------------------
Temperature
--------------------------------------------------

Definition
The temperature condition of the material or environment during the accident scenario.

Temperature can affect vapor generation, chemical stability, and the likelihood of ignition or hazardous reactions.

--------------------------------------------------
Pressure
--------------------------------------------------

Definition
The pressure condition of the material or process system during the accident
scenario.

Pressure influences the containment, release rate, and phase behavior of the
material.

Elevated pressure can increase the driving force for a release event and
accelerate discharge from equipment, while low or atmospheric pressure
conditions may affect vapor formation and downstream event development.

--------------------------------------------------
Volatility
--------------------------------------------------

Definition
The tendency of a substance to vaporize.

High volatility substances can easily form flammable or toxic vapor clouds that
may contribute to explosion or toxic exposure hazards.


--------------------------------------------------
Combustibility
--------------------------------------------------

Definition
Whether the material is capable of burning in the presence of an ignition source.

Combustible materials can participate in fires or explosions when mixed with air and exposed to ignition.


--------------------------------------------------
ToxicSubstance
--------------------------------------------------

Definition
Whether the material has toxic properties that can cause harm to humans or the
environment.

Toxic substances may produce hazardous exposure through released vapor,
downstream dispersion events, or direct contact.


--------------------------------------------------
Asphyxiant
--------------------------------------------------

Definition
Whether the substance can cause oxygen displacement or interfere with oxygen
transport in the body.

Asphyxiants may lead to suffocation or oxygen deficiency hazards in confined or
poorly ventilated spaces.


--------------------------------------------------
Conductivity
--------------------------------------------------

Definition
The electrical conductivity property of the material.

Low conductivity liquids may accumulate static electricity during transfer operations, increasing the risk of static discharge ignition.


--------------------------------------------------
IgnitionSource
--------------------------------------------------

Definition
The source of energy that can ignite a flammable mixture.

Examples include static electricity sparks, open flames, hot surfaces, electrical equipment, or mechanical sparks.


--------------------------------------------------
Confinement
--------------------------------------------------

Definition
The degree to which flammable or hazardous material is enclosed within a
confined space.

High confinement can increase explosion overpressure and significantly
influence explosion severity.


--------------------------------------------------
MechanicalFailure
--------------------------------------------------

Definition
A physical failure of equipment that contributes to the accident.

This may include rupture, leakage, seal failure, structural failure,
refractory degradation, or malfunction of process equipment that leads to loss
of containment or abnormal process behavior.

If the report describes a plausible or observed physical failure in the
analysis section, extract it as a MechanicalFailure even if the report does not
confirm it as the exact root cause.

If a mechanical failure clearly occurred and contributed to the accident,
but the exact failed component or exact failure mode cannot be determined
from the incident description, use "Unknown mechanical failure" as the name.

Use "Not specified" only when the incident description does not provide enough
support to identify whether a mechanical failure should be represented at all.

--------------------------------------------------
InitiatingEvent
--------------------------------------------------

The first abnormal operational or process event that initiates the accident
sequence within the process system.

Prefer events that represent a process upset or system disturbance.

Do NOT use an observed consequence such as overpressure, explosion, or fire as
the InitiatingEvent if it can be explained as the result of other identified
causes such as mechanical failure or process conditions.

If a concrete MechanicalFailure is identified, it should generally precede or
explain the InitiatingEvent, rather than being replaced by it.

--------------------------------------------------
IgnitionSource Special Rule
--------------------------------------------------

If ignition clearly occurred in the incident, but the exact ignition source
cannot be determined from the incident description, use
"Unknown ignition source" as the name.

Use "Not specified" only when the incident description does not provide enough
support to identify whether an ignition source should be represented at all.
